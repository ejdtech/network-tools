About the Port Number Reference

A port number identifies a particular service on a computer or network device. If an IP address is the address of a building, the port number is the door for one specific service inside it. Web servers listen on port 80 or 443, SSH on 22, DNS on 53 and so on. Firewall rules, troubleshooting and security reviews all depend on knowing which port belongs to which service. This page lists the common ones, so you can look them up in seconds.

Port ranges

The IANA registry splits the 65,536 port numbers into three ranges. System ports (0 to 1023), often called well-known ports, are for core services such as SSH, DNS and HTTP. User ports (1024 to 49151), often called registered ports, are for applications that registered a number. Dynamic or private ports (49152 to 65535) are never assigned, and operating systems use them for the temporary source ports of outgoing connections. In practice, the exact temporary range depends on the system: Windows uses 49152 to 65535 and Linux defaults to 32768 to 60999.

TCP and UDP

TCP sets up a connection and guarantees delivery in order, which suits web pages, email and remote login. UDP sends messages without a connection, which is faster and suits DNS lookups, time sync, VoIP and streaming. Some services use both, such as DNS on port 53. A TCP port and a UDP port with the same number are separate, so a firewall rule must name the protocol.

Checking ports on your own systems

On Linux, ss -tulpn lists listening TCP and UDP ports with their processes (run it as root to see all process names). On Windows, netstat -ano shows ports with process IDs, and PowerShell's Get-NetTCPConnection -State Listen lists listeners. To test whether a remote port is reachable, use nc -zv host 443 on Linux or macOS, or Test-NetConnection host -Port 443 in PowerShell.

Security tips

Close services you do not use, and allow only the ports you need through the firewall. Do not expose Remote Desktop (3389), SMB (445), database ports or management interfaces directly to the internet. Use a VPN or a gateway instead. Prefer the encrypted version of a service: SSH instead of Telnet, SFTP or FTPS instead of FTP, IMAPS instead of IMAP, and SNMPv3 instead of SNMP v1 or v2c. Keep in mind IANA's own warning that traffic on a registered port does not prove it is the assigned service or that it is legitimate, so judge traffic by what you actually know about it.

Frequently asked questions

Does ping use a port?

No. Ping uses ICMP, which sits below TCP and UDP and has no port numbers. That is why a server can answer ping while a particular port is closed, and the other way round.

Can a service run on a different port?

Yes. Port numbers are conventions, and administrators often move services, for example running a web server on 8080 or SSH on a non-standard port. This list shows the usual defaults.

What is the difference between port 80 and 443?

Port 80 carries plain HTTP, and port 443 carries HTTPS, which is HTTP protected by TLS encryption. Port 443 also carries QUIC (HTTP/3) over UDP.

What does "Common convention" mean?

Some popular software, such as Redis, Grafana or Kubernetes, uses a default port that was never officially assigned to it by IANA. Those entries are tagged so you know the number is a widely used default, not a standard.

Where does the data come from?

The entries follow the IANA Service Name and Transport Protocol Port Number Registry, plus common defaults for popular software. This is a short list for everyday use, so the registry has the complete one.

Can this tool tell me if a port is open on a server?

No. It is a reference list. A browser page cannot open arbitrary connections to other servers, so checking a live port needs a command-line tool such as the ones above.

Is my search stored?

No. The list is part of this page and searches run on your own device. EJD Tech has no server-side code or database.
